# Розслідування: Хто винен у порожнечі (Undefined vs Null)

| № | Сцена | Що вивелося | Хто винен | Як уникнути |
|---|---|---|---|---|
| 1 | Змінна без значення | `undefined` | JavaScript (автоматично) | Одразу давати змінній початкове значення при створенні. |
| 2 | Свідоме обнулення змінної | `null` | Розробник (свідомо) | Якщо порожнеча логічна — уникати не треба, це нормальний код. |
| 3 | Виклик функції без аргументу | `undefined` | JavaScript (автоматично) | Задати параметру значення за замовчуванням: `function greet(user = 'Guest')`. |
| 4 | Правильне повернення результату | `5` (число) | Ніхто (все правильно) | Уникати не потрібно, код працює ідеально і повертає суму чисел. |
| 5 | Забули написати `return` | `undefined` | JavaScript (автоматично) | Обов'язково додати в кінці функції команду `return result;`. |
| 6 | Пустий оператор `return;` | `undefined` | JavaScript (автоматично) | Якщо функція має щось повертати, не залишайте `return` порожнім. |
| 7 | Пошук ключа, якого немає в об'єкті | `undefined` | JavaScript (автоматично) | Додати властивість `age` в об'єкт або перевіряти її наявність через `if ('age' in user)`. |
| 8 | Поле об'єкта свідомо пусте | `null` | Розробник (свідомо) | Це правильна архітектура, якщо у людини дійсно немає по батькові. |
| 9 | Пошук індексу, якого немає в масиві | `undefined` | JavaScript (автоматично) | Перед викликом перевіряти, чи індекс не більший за довжину масиву (`index < arr.length`). |
| 10 | Пошук ключа у вкладеному об'єкті | `undefined` | JavaScript (автоматично) | Використовувати безпечний оператор опціонального ланцюжка: `user.address?.street`. |


Це null — розробник свідомо сказав, що тут порожньо
Це undefined — JavaScript сам поставив або значення не задано
Це не є порожнім значенням: <number, 0>
Це не є порожнім значенням: <string, >
Це не є порожнім значенням: <array, >
Це не є порожнім значенням: <boolean, false>
